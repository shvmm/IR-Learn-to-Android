Firmware & setup

1. Download the source package. In an ESP-IDF master environment, set the target to esp32 or esp32s3, choose your receiver GPIO under IR Code Studio in menuconfig, then build and flash. The included README has both USB configurations.

2. Close ESPHome logs and idf.py monitor before connecting here. The serial port must be free. Open this HTML file in desktop Chrome or Edge. If local-file USB access is blocked by your browser, serve the file on localhost or HTTPS. Open it in its own tab if an embedded preview blocks serial access.

3. Click Learn, press and release one button, then wait for the prompt to press it again. After 600 ms of silence, each press is complete. With Double-press verification on, two matching captures unlock naming and saving. Turn the switch off to save after one complete press. The setting is remembered in this browser and cannot be changed during capture. Comparison allows normal timing jitter and ignores NEC hold-repeat frames; different codes or incomplete captures must be learned again. Protocols that deliberately change their code between presses may not verify.

Receiver modules do not measure the IR carrier frequency. It is exported as null, not guessed. Classic ESP32 captures are limited to about 512 RMT symbols; the S3 buffer holds 2048. Frames near the buffer limit are rejected. A 15 ms idle interval ends a frame by default. Long AC messages may require tuning and repeated validation.

Validation: Source targets the current ESP-IDF RMT API. Firmware has not been compiled or tested on physical hardware in this environment. This app captures signals; transmitting requires additional hardware and firmware.

NEC mode converts the command’s bit order and uses standard timings. Neither mode preserves capture timestamps or separate repeat frames. Keep your native JSON for those details.

Raw mode exports the first complete data frame, preserving its recorded durations. Additional frames and repeat frames are omitted. No missing inter-frame gaps are invented.
